Why Modules Matter

  • Improved Performance

CommonJS Modules

Traditional Node.js

  • require() to import
  • module.exports to export
  • Documentation
  • Pros: widely supported in Node.js
  • Cons: not standard ES syntax

// math.js
function add(a, b) { return a + b; }
module.exports = { add };
        

// app.js
const math = require("./math");
console.log(math.add(2, 3)); // 5

ES Modules

Modern JavaScript

  • import to import
  • export to export
  • Documentation
  • Pros: aligns with modern JS, compatible with browser code
  • Cons: older Node.js modules may still use CommonJS

// math.mjs
export function add(a, b) { return a + b; }
        

// app.mjs
import { add } from "./math.mjs";
console.log(add(2, 3)); // 5

package.json

Project Package Management

  • Every Node.js project typically has a package.json file.
  • Use npm commands to alter.
  • Project metadata (name, version, description).
  • Dependencies (packages your app needs).
  • Scripts (commands like start or test).

// terminal in the project directory
npm init -y

Installing Packages

Project Package Management

  • Package search to find packages.
  • npm install to install packages.
  • Example: lodash.

// terminal in the project directory
npm install lodash              // installs as project level production dependency
npm install lodash --save-dev   // installs as project level dev dependency
npm install -g lodash           // installs globally (available outside project)
        

// import lodash
const _ = require("lodash");    // CommonJS
import _ from "lodash";         // ES Modules
        

// example code
node lodash.js          // CommonJS
node lodash.mjs         // ES Modules
