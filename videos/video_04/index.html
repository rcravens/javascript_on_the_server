Node.js Fundamentals

Single-Threaded / Non-Blocking

  • Single-threaded Event Loop: The main JavaScript execution happens on a single thread. This thread handles the call stack and the event loop, processing JavaScript code sequentially.
  • Blocking Threads for I/O: When an asynchronous operation (like reading a file or making an HTTP request) is initiated, the main thread offloads this task to a background thread from the libuv thread pool.
  • Non-blocking Execution: While the background thread is busy with the I/O operation, the main event loop is free to continue executing other JavaScript code. It does not wait for the I/O operation to complete.
  • Callbacks and Event Queue: Once the background operation finishes, its result is placed in the event queue. The event loop periodically checks this queue and, when the call stack is empty, pushes the callback function associated with the completed operation onto the call stack for execution on the main thread.

Callbacks

  • A callback is a function passed as an argument to another function, intended to be executed after the completion of an asynchronous operation.
  • The calling function initiates the async tasks and then passes control to the callback function when finished.
  • Errors are typically handled by passing an Error object as the first argument to the callback function.
  • Deeply nested callbacks can lead to "callback hell" or "pyramid of doom", making code difficult to read, understand, and maintain, especially with multiple dependent async operations.

// callback_example.js

const fs = require('fs');

fs.readFile('file.txt', 'utf8', (err, data) => {
    if (err) {
        console.error('Error reading file:', err);
        return;
    }
    console.log('File content:', data);
});
        

// terminal window
node callback_example.js

Promises - Modern Alternative

  • A Promise is an object representing the eventual completion (or failure) of an async operation and its resulting value. It acts as a placeholder for a value that will be available in the future.
  • Promises allow for a more structured and linear flow using .then(), .catch(), and .finally() methods. Instead of passing a callback, the async function returns a Promise object, and subsequent operations are chained to it.
  • Promises provide a centralized error handling mechanism through the .catch() method, which can catch errors anywhere in the promise chain.
  • Promises improve readability and maintainability by flattening the code structure and avoiding deep nesting, especially when chaining multiple async operations.

// promise_example.js

const fs = require('fs/promises'); // Using the promise-based fs module

fs.readFile('file.txt', 'utf8')
    .then(data => {
        console.log('File content:', data);
    })
    .catch(err => {
        console.error('Error reading file:', err);
    });
        

// terminal window
node promise_example.js

Async / Await

Syntactic Sugar

  • async/await is syntactic sugar built on top of Promises, introduced in ES8, making async code appear and behave more like sync code.
  • An async function is a function that returns a Promise. The await keyword can only be used inside an async function and pauses the execution of the async function until the awaited Promise settles (resolves or rejects).
  • Significantly enhances readability and simplifies error handling using the standard try..catch blocks, making async code easier to reason about.

// async_await_example.js

import fs from 'fs/promises'; // Using the promise-based fs module

console.log('Start');

try {
    const data = await fs.readFile('file.txt', 'utf8');
    console.log('File content:', data);
} catch (err) {
    console.error('Error reading file:', err);
}

console.log('End');
        

// terminal window
node async_await_example.js

Key Takeaways

  • Node never blocks the main thread fo I/O.
  • Understanding async patterns is crucial for building web servers.
  • Promises and async/await are preferred over callbacks for modern code.
