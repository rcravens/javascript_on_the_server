Working with Data

Why use Databases?

  • File-based storage is simple but has limitations:
    • 👉 Not suitable for high concurrency.
    • 👉 File I/O can block if not handled asynchronously.
    • 👉 No indexing, transactions, or query language.
  • Databases provide:
    • 👉 Structured data storage.
    • 👉 Query capabilities (SQL or NoSQL).
    • 👉 Atomicity, Consistency, Isolation, and Durability (ACID) guarantees for reliability.

Types of Databases

  • SQLite (Relational, file-based) sqlite official sqlite node:
    • 👉 Lightweight, serverless, great for small projects or prototyping.
    • 👉 Supports standard SQL.
  • PostgreSQL (Relational, server-based) postgresql official:
    • 👉 Full-featured relational DB.
    • 👉 Supports complex queries, transactions, indexing.
  • MongoDB (NoSQL, document-based) mongodb official:
    • 👉 Stores JSON-like documents.
    • 👉 Flexible schema, good for dynamic or unstructured data.

Create DB Table

SQLite Example


// Person.js (partial)
import sqlite from "sqlite";
import sqlite3 from "sqlite3";

const DB_PATH = "people.db";

let db;

async function initDB() {
  if (!db) {
    db = await sqlite.open({
      filename: DB_PATH,
      driver: sqlite3.Database
    });

    // Migration: create the persons table if it doesn't exist
    await db.run(`
      CREATE TABLE IF NOT EXISTS persons (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        first_name TEXT NOT NULL,
        last_name TEXT NOT NULL,
        email TEXT NOT NULL UNIQUE
      )
    `);
  }
  return db;
}

Create

CRUD Operations


// Person.js (partial)

// ------ Create: insert new, fail if already exists
static async create(first_name, last_name, email) {
    const db = await initDB();

    try {
        await db.run(
            `INSERT INTO persons (first_name, last_name, email) VALUES (?, ?, ?)`,
            first_name,
            last_name,
            email
        );
        return new Person(first_name, last_name, email);
    } catch (err) {
        if (err.message.includes("UNIQUE constraint failed")) return null;
        throw err;
    }
}

Read

CRUD Operations


// Person.js (partial)

// ------ Read: find by email
static async read(email) {
    const db = await initDB();
    const row = await db.get(`SELECT * FROM persons WHERE email = ?`, email);
    return row ? new Person(row.first_name, row.last_name, row.email) : null;
}

Update

CRUD Operations


// Person.js (partial)

// ------ Update: update first/last name by email
static async update(first_name, last_name, email) {
    const db = await initDB();
    const result = await db.run(
        `UPDATE persons SET first_name = ?, last_name = ? WHERE email = ?`,
        first_name,
        last_name,
        email
    );

    if (result.changes === 0) return null;
    return new Person(first_name, last_name, email);
}

Delete

CRUD Operations


// Person.js (partial)

// ------ Delete: remove by email
static async delete(email) {
    const db = await initDB();
    const person = await Person.read(email);
    if (!person) return null;

    await db.run(`DELETE FROM persons WHERE email = ?`, email);
    return person;
}

Key Takeaways

  • Choosing a database depends on project size, complexity, and concurrency needs.
  • SQLite is simple and file-based but supports SQL queries.
  • MongoDB is flexible but requires learning NoSQL concepts.
  • PostgreSQL is robust for production systems.
