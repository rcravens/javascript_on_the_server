Working with Data

Why File-Based Storage?

  • Simple way to persist data between server restarts.
  • Useful for small projects or prototypes.
  • Avoids complexity of setting up a database.
  • Limitations:
    • 👉 Not suitable for high concurrency.
    • 👉 File I/O can block if not handled asynchronously.
    • 👉 No indexing, transactions, or query language.

Reading JSON Data

Simple Example


// read_file.js
import fs from "fs/promises";

async function read_json(path) {

    try {
        const data = await fs.readFile(path, "utf-8");
        return JSON.parse(data);
    } catch (err) {
        console.error("Error reading file:", err);
    }
}

const data_path = "users.json";

let users = await read_json(data_path);

console.log(users);
console.log(users[0]);
console.log(users[0].email);
        

// terminal window
node read_file.js

Writing JSON Data

Simple Example


// write_file.js
import fs from "fs/promises";

async function write_json(path, data) {
    try {
        await fs.writeFile(path, JSON.stringify(data, null, 2));
        console.log("Data saved!");
    } catch (err) {
        console.error("Error writing file:", err);
    }
}

const data_path = "users2.json";

let users = [];
const user = {
    "first": "Bob",
    "last": "Cravens",
    "email": "bcravens@example.com"
}
users.push(user);

await write_json(data_path, users);
        

// terminal window
node write_file.js

Create / Read / Update / Delete

Data Operations

  • Assume email field is unique and primary key.
  • Create - Insert new record. Fail if already exists.
  • Read - Find a person. Return null if not found.
  • Update - Find person and update. Fail if not found.
  • Delete - Find person and delete. Fail if not found.

Create

CRUD Operations


// User.js (partial)

// ------ Create: insert new, fail if already exists
static async create(first_name, last_name, email) {
    const users = await read_json(data_path);
    const exists = users.find((user) => user.email === email);
    if (exists) return null;

    const user = new User(first_name, last_name, email);
    users.push(user);
    await write_json(data_path, user);
    return user;
}

Read

CRUD Operations


// User.js (partial)

// ------ Read: find by email
static async read(email) {
    const users = await read_json(data_path);
    const user = users.find((user) => user.email === email);
    return user || null;
}

Update

CRUD Operations


// User.js (partial)

// ------ Update: update first/last name by email
static async update(first_name, last_name, email) {
    const users = await read_json(data_path);
    const index = users.findIndex((user) => user.email === email);
    if (index === -1) return null;

    users[index].first_name = first_name;
    users[index].last_name = last_name;

    await write_json(data_path, users);
    return users[index];
}

Delete

CRUD Operations


// User.js (partial)

// ------ Delete: remove by email
static async delete(email) {
    const users = await read_json(data_path);
    const index = users.findIndex((user) => user.email === email);
    if (index === -1) return null;

    const [removed_user] = users.splice(index, 1);
    await write_json(data_path, users);
    return removed_user;
}

Key Takeaways

  • Works well for prototypes or small apps.
  • Avoid simultaneous writes in production; can cause race conditions.
  • Provides a stepping stone before using a proper database.
