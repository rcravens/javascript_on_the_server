HTML Forms

  • Client Side - HTML Form:
    • 👉 Forms allow user to enter and submit data to the server.
    • 👉 Set the HTTP verb / method: method="POST".
    • 👉 Set the end-point: action="/people".
    • 👉 Provide input, textarea, and other elements for data entry.
    • 👉 Data is included in the request data submitted to the server.
  • Server Side - Request / Response:
    • 👉 Node streams incoming data as part of the request.
    • 👉 Parse data into a usable form.
    • 👉 List for "data" and "end" events.

// server.js (partial)

const router = new Router();
registerRoutes(router);

const server = http.createServer(async (req, res) => {
    const url = new URL(req.url, `http://${req.headers.host}`);
    const parts = url.pathname.split("/").filter(Boolean);

    // Handle _method override
    const method = req.method === "POST" && url.searchParams.get("_method")
            ? url.searchParams.get("_method").toUpperCase()
            : req.method;

    try {
        await router.handle(req, res, method, parts);
    } catch (err) {
        console.error("Error handling request:", err);
        res.writeHead(500, { "Content-Type": "text/plain" });
        res.end("Internal Server Error");
    }
});

Server Side - Parsing

// Router.js (partial)

export default class Router {

    static parseBody(req) {
        return new Promise((resolve, reject) => {
            let data = '';
            req.on('data', chunk => data += chunk);
            req.on('end', () => {
                try {
                    const contentType = req.headers['content-type'] || '';
                    if (contentType.includes('application/json')) {
                        resolve(JSON.parse(data || '{}'));
                    } else if (contentType.includes('application/x-www-form-urlencoded')) {
                        const params = new URLSearchParams(data);
                        resolve(Object.fromEntries(params.entries()));
                    } else {
                        resolve({});
                    }
                } catch (err) {
                    reject(err);
                }
            });
        });
    }
}

Other Considerations

  • Sanitization:
    • 👉 Performed at "point of use".
    • 👉 Prevents XSS and injection attacks.
    • 👉 EJS example: <%= variable %> performs HTML sanitization, <%- variable %> DOES NOT.
    • 👉 SQL: use "parameterized queries" to sanitize variables used in queries.
  • Validation:
    • 👉 Performed immediately...before storing or using any data.
    • 👉 Inspection to ensure data conforms to predefined rules (length, min/max, email...).
    • 👉 Data that fails inspection should be sent back to browser for the user to edit.

Key Takeaways

  • Listen for "data" and "end" to parse POST body.
  • Forms are the foundation for user input in web apps.
  • Validation should be performed immediately.
  • Sanitization should be performed at point-of-use.
