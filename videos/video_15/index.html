Why Sessions & Cookies?

  • HTTP is stateless: each request is independent.
  • Cookies:
    • 👉 Allow servers to remember clients across requests.
    • 👉 Can originate on the client (browser) or the server.
    • 👉 Travel in the request / response headers: server --> client --> server.
    • 👉 Small pieces of information.
    • 👉 Data is available on the client.
    • 👉 Usage: session ID, personalization, tracking/analytics...
  • Sessions:
    • 👉 Track user-specific data on the server by associating it with a session ID stored in a cookie.
    • 👉 Data is not available on the client.
    • 👉 Session data should be persistent while user browses website.
    • 👉 Usage: flash message, form validation, cart management...

parseCookies(req) {
    const list = {};
    const cookieHeader = req.headers.cookie || "";
    cookieHeader.split(";").forEach(cookie => {
        const parts = cookie.split("=");
        if (parts.length === 2) list[parts[0].trim()] = decodeURIComponent(parts[1].trim());
    });
    return list;
}

Sessions

Simple File-Based Manager


// app/SessionManager.js (partial)

class SessionManager {
    constructor({ storageDir = null } = {}) {
        this.sessions = {};
        this.storageDir = storageDir;
        if (storageDir) fs.mkdirSync(storageDir, { recursive: true });
    }

    createSession() {
        const id = randomBytes(16).toString("hex");
        this.sessions[id] = { flash: {} }; // initialize flash container
        if (this.storageDir) this.saveSessionToFile(id);
        return id;
    }

    getSession(id) {
        if (!id) return null;
        if (this.sessions[id]) return this.sessions[id];
        if (this.storageDir) {
            const filePath = path.join(this.storageDir, `${id}.json`);
            if (fs.existsSync(filePath)) {
                const data = JSON.parse(fs.readFileSync(filePath));
                this.sessions[id] = data;
                if (!this.sessions[id].flash) this.sessions[id].flash = {};
                return data;
            }
        }
        return null;
    }

    saveSessionToFile(id) {
        if (!this.storageDir || !this.sessions[id]) return;
        const filePath = path.join(this.storageDir, `${id}.json`);
        fs.writeFileSync(filePath, JSON.stringify(this.sessions[id], null, 2));
    }
}

Simple File-Based Manager


// app/SessionManager.js (partial)

// Flash helper methods
req.flash = {
    set: (key, value) => {
        req.session.flash[key] = value;
        if (this.storageDir) this.saveSessionToFile(sessionId);
    },
    get: (key) => {
        const value = req.session.flash[key];
        delete req.session.flash[key];  // remove after reading
        if (this.storageDir) this.saveSessionToFile(sessionId);
        return value;
    },
    all: () => {
        const value = { ...req.session.flash };
        req.session.flash = {};  // clear all flash
        if (this.storageDir) this.saveSessionToFile(sessionId);
        return value;
    }
};

Key Takeaways

  • Cookies store client-side data.
  • Sessions can store server-side data linked via a cookie (session ID).
  • Production Considerations:
    • 👉 Use signed/encrypted cookies.
    • 👉 Persistent, redundant, scalable storage solution (e.g., dedicated Redis server)
    • 👉 Consider server-side session storage with libraries like express-session.
